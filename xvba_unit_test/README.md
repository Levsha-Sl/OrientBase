# Проверка импорта

Запуск из корня проекта в Windows PowerShell или PowerShell 7:

```powershell
.\xvba_unit_test\Test-Import.ps1
```

Нужен установленный Excel с разрешённым доступом к объектной модели VBA.
Скрипт не меняет настройки безопасности. Он создаёт отдельный скрытый экземпляр
Excel и временную книгу, загружает текущие модули и закрывает книгу без сохранения.
Рабочая книга `orient_sportsman_database.xlsm` не открывается и не изменяется.

Проверяются чтение CSV в Windows-1251 и UTF-8 с BOM, заголовок и значения полей,
дубли внутри файла, сверка с текущим кэшем базы, редактирование и применение
результата, повторный импорт, сохранение посторонних записей и правила Orgeo.
Листы представления и диалоги заменены заглушками; их оформление и взаимодействие
с кнопками проверяются вручную.

## Ручная проверка

1. Загрузить изменённые VBA-модули в тестовую копию книги и инициализировать её.
2. Выполнить `Base.Import`, выбрав CSV, созданный текущим `Base.Export`.
3. На листе списка `Import` проверить пары «Инф.базы / Обнов» и строки «Новый».
   До принятия списка текущая база должна оставаться прежней.
4. Изменить строку «Обнов» и нажать «Выгрузить в базу». Проверить результат
   и повторить импорт: существующие участники не должны дублироваться.
5. Проверить отмену выбора файла, CSV только с заголовком, неверную дату и дубль
   участника. При ошибке новый список не должен создаваться.

CSV передаёт значения полей целиком, включая пустые даты и период страховки;
их можно исправить в списке до принятия. `TIMESTAMP` устанавливается при принятии,
как в существующем процессе Orgeo. Формат и процедуры экспорта не меняются.
